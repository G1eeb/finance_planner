# Finance Planner — сервис финансового планирования

Консольное приложение для учёта личных доходов и расходов,
контроля месячного бюджета и отслеживания финансовых целей.

## Возможности

### Операции (доходы и расходы)
- добавление операций с указанием типа, суммы, категории и даты;
- просмотр списка операций;
- поиск операций по подстроке категории;
- сортировка операций по сумме;
- статистика: доходы, расходы, баланс, разбивка по категориям.

### Финансовые цели
- добавление целей с указанием названия и целевой суммы;
- пополнение целей;
- просмотр прогресса в процентах;
- сортировка целей по прогрессу;
- суммарные накопления по всем целям;
- список достигнутых целей.

### Проверка бюджета
- разовый расчёт: возможна ли планируемая трата без превышения бюджета;
- предупреждение, если после покупки останется менее 5000 руб.;
- расчёт суммы превышения, если трата невозможна.

## Предметная область

Основные сущности предметной области:

- **Transaction** — операция (доход или расход);
- **Goal** — финансовая цель (накопление на покупку).

Бюджет не является сущностью — это разовый калькулятор,
реализованный набором функций.

## Основные классы

### `Transaction` — операция

Объект `Transaction` представляет одну операцию — доход или расход.

**Атрибуты:**
- `id` — уникальный идентификатор операции;
- `type` — тип операции: `"income"` или `"expense"`;
- `amount` — сумма операции;
- `category` — категория (например, «Техника», «Зарплата»);
- `date` — дата операции в ISO-формате (`YYYY-MM-DD`).

**Методы:**
- `__init__()` — конструктор с валидацией типа и суммы;
- `__str__()` — читаемое строковое представление;
- `is_income()` — является ли операция доходом;
- `is_expense()` — является ли операция расходом;
- `validate_type(type_)` — статический метод: проверка типа;
- `validate_amount(amount)` — статический метод: проверка суммы;
- `from_dict(data)` — класс-метод: создание из словаря (из JSON);
- `to_dict()` — преобразование в словарь (для JSON).

### `Goal` — финансовая цель

Объект `Goal` представляет накопление на конкретную покупку.

**Атрибуты:**
- `id` — уникальный идентификатор цели;
- `name` — название цели;
- `target` — целевая сумма;
- `saved` — накопленная сумма (по умолчанию 0).

**Методы:**
- `__init__()` — конструктор с валидацией;
- `__str__()` — читаемое строковое представление с прогрессом;
- `add_to_goal(amount)` — пополнить цель;
- `get_progress()` — процент выполнения (0–100);
- `is_achieved()` — достигнута ли цель;
- `validate_target(target)` — статический метод;
- `from_dict(data)` — класс-метод: создание из словаря;
- `to_dict()` — преобразование в словарь.

## Взаимодействие объектов

Объекты `Transaction` и `Goal` **независимы** друг от друга:
- операции хранят фактические доходы и расходы;
- цели — отдельные накопления;
- связи между ними нет (это соответствует предметной области).

Коллекции объектов:
- `transactions: list[Transaction]`
- `goals: list[Goal]`

Функции работы с коллекциями (`add_transaction`, `find_transactions_by_category`,
`sort_goals_by_progress` и т. д.) остаются **обычными функциями** — они не относятся
к поведению одного конкретного объекта.

## Хранение данных

Данные приложения хранятся в JSON-файлах:

- `data/transactions.json` — операции;
- `data/goals.json` — цели.

При загрузке данные из JSON преобразуются в объекты `Transaction` и `Goal`
(через `from_dict`). При сохранении объекты преобразуются обратно в словари
(через `to_dict`) и записываются в JSON.

Формат JSON сохраняется с ПР2 — переход к объектной модели **не меняет**
структуру файлов данных.
